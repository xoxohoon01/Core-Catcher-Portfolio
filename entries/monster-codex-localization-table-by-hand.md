# 몬스터 이름 하나 넣으려고 로컬라이제이션 테이블을 손으로 역설계한 이야기

날짜: 2026-10-08
태그: Unity, 로컬라이제이션, 에셋 파이프라인, 트러블슈팅

## 배경

도감(Codex) 화면에 몬스터 탭을 추가하면서, 종족 이름을 화면에 띄우려고 보니 그 이름을 담을 로컬라이제이션 테이블이 아직 없었다. 아티팩트·패시브·캐릭터는 이미 각자 테이블이 있었는데, 몬스터는 그동안 이름을 보여줄 화면 자체가 없었어서 한 번도 만들 일이 없었던 거다.

## 문제

보통이라면 유니티 에디터의 Localization Tables 창을 열어서 "New Table Collection" 버튼 몇 번 누르면 끝나는 일이다. 그런데 에디터 UI를 직접 조작하지 않고 코드·텍스트 파일 위주로 작업을 진행하던 흐름이라, 그 창을 열지 않고 테이블을 만들어야 하는 상황이었다. 처음엔 "이 부분은 나중에 에디터에서 직접 만들자"로 넘기는 게 제일 안전한 선택이었다.

## 해결 과정

그냥 넘기기 전에, 이미 있는 `ArtifactTable`(아티팩트 설명에 쓰는 테이블)의 실제 파일들을 전부 열어서 구조를 뜯어봤다. 로컬라이제이션 테이블 하나는 겉보기엔 에셋 하나처럼 보이지만 실제로는 세 종류 파일로 쪼개져 있었다:

1. **Shared Data** — 키 목록(이름, ID)을 담은 파일. 언어와 무관한 "목차" 역할
2. **Table Collection** — 이 목차와 각 언어별 테이블을 묶어주는 파일
3. **언어별 테이블**(ko, en 등) — 실제 번역 문자열이 들어있는 파일

이 세 파일이 전부 GUID로 서로를 참조하고 있었다. 거기서 끝이 아니라, Addressables라는 별도 리소스 관리 시스템에도 이 테이블들의 주소가 등록돼 있어야 게임이 실제로 찾아낼 수 있었다 — 이 등록이 빠지면 에러도 안 나고 그냥 조용히 "번역 없음"으로 처리되기 때문에, 빠뜨려도 한참 뒤에야 알아차리기 쉬운 부분이었다.

다행히 기존 테이블을 참고 자료로 삼을 수 있었다. Shared Data 파일을 열어보니 그 파일 자신의 고유 ID와, 파일 내부에 적힌 "테이블 고유 식별자" 값이 항상 똑같았다 — 즉 새 식별자 하나만 만들면 양쪽에 그대로 재사용하면 된다는 뜻이었다. Addressables 등록 파일에 적힌 "GUID로 표시된 테이블 참조"도, 실제로는 에디터가 드롭다운으로 테이블을 고를 때 저장하는 한 가지 표현 방식일 뿐이고, 코드에서는 그냥 평범한 문자열(테이블 이름)로 넘겨도 똑같이 동작한다는 걸 패키지 소스 코드에서 확인했다.

이 세 가지(Shared Data, Table Collection, 언어별 테이블)를 기존 것과 같은 구조로 새로 작성하고, Addressables 등록 파일 세 군데에 새 항목을 한 줄씩 추가했다. 이름 값은 아직 실제 번역이 없으니 일단 종족 원문 이름("Tailless" 등)을 그대로 넣어뒀다.

## 결과 / 배운 점

- 유니티가 이 파일들을 열자마자 에러 하나 없이 깨끗하게 읽어들였고, 게임 코드에서 바로 정상적으로 이름을 조회해왔다.
- 그 뒤에 에디터에서 직접 한글 이름을 입력해도 아무 문제 없이 기존 내용과 그대로 섞여 들어갔다 — 손으로 쓴 파일이 에디터와 완전히 호환된다는 뜻이었다.
- 유니티의 전용 포맷처럼 보이는 것도 결국은 평범한 텍스트 파일이고, **이미 올바르게 동작하는 같은 종류의 에셋을 참고 자료로 삼으면** 에디터 UI 없이도 안전하게 새 데이터를 추가할 수 있다는 걸 확인했다. 다만 이건 아무 파일이나 추측해서 쓰는 게 아니라, 검증된 예시를 먼저 완전히 뜯어보고 그 구조를 그대로 복제한다는 전제가 있을 때만 믿을 만한 방법이라는 것도 같이 적어둔다.
