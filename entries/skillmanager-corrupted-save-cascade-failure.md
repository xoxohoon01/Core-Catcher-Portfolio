# 세이브 파일 하나가 깨졌을 뿐인데, 멀쩡한 캐릭터가 통째로 사라졌다

날짜: 2026-11-18
태그: Unity, C#, 디버깅, 저장 시스템

## 배경

이 게임은 캐릭터마다 따로 스킬 트리를 갖고 있고, 해금 상태는 캐릭터 이름을 키로 쓰는 JSON 파일로 저장된다. 예를 들어 레이븐의 스킬 해금 상태는 `RavenSkill.json`, 아서는 `ArthurSkill.json`에 저장된다. 게임이 켜질 때 `SkillManager`가 모든 캐릭터의 저장 파일을 한 번에 읽어서 메모리 위의 딕셔너리에 올려두고, 이후 스킬 사용 판정은 전부 이 딕셔너리를 조회하는 식이다.

구조 자체는 단순했다. 문제는 "파일을 읽다가 실패하면 어떻게 되는가"를 아무도 깊게 생각해보지 않았다는 데 있었다.

## 문제

레이븐으로 플레이하면 기본공격이든 스킬이든 손만 대면 콘솔에 빨간 에러가 떴다.

```
KeyNotFoundException: The given key 'Raven' was not present in the dictionary.
SkillManager.CheckSkillUnlocked (System.String characterName, System.Int32 id)
```

이상한 건 레이븐이 존재하지 않는 캐릭터가 아니라는 점이었다. 캐릭터 선택도 정상이었고, 스킬 트리 데이터도 멀쩡히 있었다. 그런데 "딕셔너리에 'Raven'이라는 키가 없다"는 건, 게임이 켜지는 순간 레이븐이라는 캐릭터 자체가 애초에 등록조차 안 됐다는 뜻이었다.

## 해결 과정

의심할 곳은 캐릭터들을 등록하는 로딩 루프 하나뿐이었다. 코드를 보니 구조는 이랬다 — 모든 캐릭터를 순서대로 돌면서, 저장 파일이 있으면 그걸 읽어 딕셔너리에 넣고, 없으면 새로 만들어서 넣는다. 저장 파일을 읽는 함수 쪽을 보니 역직렬화(JSON을 다시 객체로 바꾸는 과정)가 실패하면 예외를 그 안에서 조용히 잡아 로그만 남기고 `null`을 돌려주고 있었다. "저장 파일이 깨져 있어도 게임이 죽진 않게" 짜둔 방어 코드였다.

그런데 그 `null`을 받는 쪽은 아무 방어가 없었다. 돌려받은 값에 바로 `.Exists(...)`를 호출하다가 `null`을 참조하며 `NullReferenceException`이 터졌고, 이 예외가 캐릭터를 순회하는 `foreach` 루프를 그 자리에서 끝내버렸다. 즉 "저장 파일이 깨진 캐릭터 하나만 문제가 생기는" 게 아니라, **그 캐릭터 차례에서 루프 전체가 멈춰버려서 뒤 순서로 처리될 캐릭터는 등록 자체가 안 되는** 구조였던 것이다.

실제로 로컬에 남아있던 `RavenSkill.json`을 열어보니 내용이 전부 공백이었다 — 저장 도중 게임이 비정상 종료되면서 다 쓰지 못한 파일로 보였다. "저장 파일이 깨졌다"는 흔한 상황 하나가, "방어 코드가 예외를 삼키고 null을 돌려준다 → 호출하는 쪽은 그 null을 못 받아낸다 → 루프 전체가 끊긴다"는 세 단계를 거쳐 전혀 상관없어 보이는 캐릭터까지 덮치는 결과로 번진 것이다.

고치는 방법은 명확했다. `null`을 받으면 "저장 파일이 아예 없을 때"와 똑같이 취급해서 미해금 상태로 새 리스트를 만들어주면 된다.

```csharp
List<Skill> skillData = DataManager.Load<List<Skill>>($"{character.characterName}Skill");

if (skillData == null)
{
    // 세이브 파일이 손상돼 역직렬화에 실패한 경우 — 미해금 상태로 새로 생성해 복구
    skillData = new List<Skill>();
}
```

이렇게 하면 루프가 끊기지 않을 뿐 아니라, 바로 뒤에서 정상적인 JSON으로 다시 저장되기 때문에 다음 플레이부터는 알아서 복구된다.

## 결과 / 배운 점

- **"예외를 잡아서 조용히 넘긴다"는 방어 코드는, 그 반환값을 받는 쪽까지 같이 봐야 완성된다.** 실패를 삼키고 `null`을 돌려주는 쪽만 안전해지고, 그걸 받는 쪽이 `null`을 전혀 예상하지 못하고 있으면 안전장치가 오히려 "어디서 터질지 예측할 수 없는 예외"로 바뀐다.
- **여러 항목을 한 루프로 순차 처리할 때는, 하나의 실패가 나머지 전부를 멈추는 구조인지 항상 확인해야 한다.** 이번 경우는 레이븐의 저장 파일이 깨졌는데 증상은 "레이븐을 플레이할 수 없다"로 끝나지 않고, 로딩 순서상 레이븐 뒤에 있는 캐릭터가 있었다면 그 캐릭터도 같이 등록되지 않았을 상황이었다.
- **버그 수정과 "손상된 데이터 자체의 복구"는 다른 문제다.** 코드를 고쳐서 크래시는 막았지만, 이미 깨져서 읽을 수 없게 된 파일 안의 실제 내용(어떤 스킬을 해금해뒀는지)은 되살릴 방법이 없었다. 할 수 있는 최선은 "깨진 데이터를 안전한 기본값으로 되돌리고, 그 다음부터는 다시 정상적으로 쌓이게" 만드는 것뿐이었다.
